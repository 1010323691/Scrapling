# Playbook：把整个网站做成可检索、可问答的本地知识库

来源：2026-10 把碧蓝航线 BWIKI（wiki.biligame.com/blhx，MediaWiki + 腾讯 EdgeOne WAF）做成 AI 问答知识库的完整过程。
成品：`D:\projectPath\AzurLaneMemory`（私有仓库 github.com/1010323691/AzurLane-KB），共 1.9 万页、5.8 万个检索块、954 艘舰船实体、2,071 条榜单图片识读。
本文只写**可迁移的流程与踩坑**；该站的具体实现见该仓库的 `README.md` 和 `scripts/`。

---

## 0. 先定边界（开工前）

- **不绕过登录、验证码、付费墙、WAF 限流**。用户说「用浏览器点」「换真浏览器就没额度了」时，要解释清楚：用隐身浏览器、伪装 UA/TLS、代理轮换去换更高额度，本质就是规避访问限制，不做。正常低频查几页可以，批量全站抓不行。
- 用诚实的 UA（项目名 + 联系方式）。伪造浏览器 UA 被拒后，不要继续换花样。
- 排除广告、账号页、评论、用户生成的海量子页；排除规则要落盘（如 `sources/excluded_prefixes.json`），并计入覆盖率报告。
- 只在三种情况下打断用户：需要登录凭据、涉及费用、关键范围缺失。

## 1. 侦察：API > sitemap > 静态 HTML > 浏览器

按顺序试，**拿到结构化接口就不要解析 HTML**：

| 站点类型 | 首选入口 | 说明 |
|---|---|---|
| MediaWiki（`/api.php` 能访问） | `action=query&generator=allpages&prop=revisions\|categories\|info\|pageprops&rvprop=content\|ids\|timestamp` | 一次请求取 50 页源码和元数据（机器人账号可取 500 页）；WAF 按请求计数，所以批量越大越省额度 |
| 站点有 sitemap | `robots.txt` → `Sitemap:` | Scrapling `SitemapSpider` |
| 纯 HTML | Scrapling `Fetcher` + CSS 选择器 | 有前端渲染时才用 `StealthyFetcher`，而且只抓少量页面 |

MediaWiki 常用接口：
- 清单：`list=allpages`（`apfilterredir=redirects` 列出重定向页），`list=allredirects`（与前者按 `fromid` 连接）；`siteinfo`、命名空间计数用于核对覆盖率。
- 增量：`list=recentchanges`（edit/new/log，含删除和移动；**只保留约 30 天**，超期后要重新全量清单）。
- 文件：`prop=imageinfo&iiprop=url|size|mime`，一次 50 个。**BWIKI 等站点的文件存储名是随机串，不能由文件名推算地址。**
- 渲染：`action=parse`，只用于源码里取不到内容的页面（SMW `#ask`、Lua `#invoke` 动态列表）。
- 内容来源二选一：**有信息框模板的页面用 wikitext**（模板参数是干净的键值；渲染页里有 JS 切换的隐藏值和合并单元格，会重复、会错位）；没有信息框的长文和动态列表用渲染 HTML。

## 2. 限流：先测清楚，再锁定

1. **认出拦截信号**：EdgeOne 返回 HTTP 567（Cloudflare 常见 403/429/503 和挑战页）。拦截要当成熔断处理：保存进度，以退出码 2 退出，不要硬重试。
2. **TLS 指纹**：Python `requests` 被拦、`curl` 能通，说明拦的是 Python TLS 栈。改用系统 `curl` 作为传输层（诚实 UA），而不是伪装成 Chrome。
3. **额度的口径会骗人**：按「10 分钟窗口」阶梯试探（7→8→…次）时，到 12 次才被拦；但解封后 9–10 次很快又被拦。真实口径更接近「约 1 小时 30–50 次」的滑动额度。**结论要跑几个小时才可信**，短时间试探得到的数会偏高。
4. **锁定在安全档**：本站稳定可用的是 4 次/10 分钟（150 秒/次）。被拦后等 30 分钟；**封禁期内频繁重试会延长封禁**。
5. **限速状态要落盘**（如 `state/rate.json`：窗口、档位、是否锁定、是否在封禁中），后续运行沿用。
6. **CDN 和主站分开计**：图片 CDN（patchwiki.biligame.com）1 秒 1 张从未被拦。下载走 CDN，额度留给 API。
7. 估算工期要说实话：全站约 380 次请求 × 150 秒 ≈ 16 小时。并发、代理都不能正当地缩短它；正路是申请机器人账号或 API 白名单。

## 3. 断点续抓与长任务

- 每个命名空间一个游标文件（`state/crawl_cursor_ns{N}.json`），每批成功后再写；进程被杀后从游标继续。**会话结束时后台进程会被一起杀掉**，所以游标是必需品。
- 坏批次用**二分**定位到单页（例：`MWUnknownContentModelException` 导致整批 50 页失败），坏页记入失败清单，其余照常。
- 长任务开防休眠（Windows `SetThreadExecutionState`），日志用本地时区写到 `state/crawl.log`。
- 用 `/loop` 或定时检查进度时，检查项包括：是否在封禁中、游标是否前进、失败清单是否增长。
- 「只抓变化」的增量流程：`recentchanges` → 按 pageid 重抓 → 旧版本存 `raw/history/` → 删除的页移到 `raw/deleted/` → 写变更记录。**附带的低频刷新（重定向表、分类表）加 24 小时新鲜度判断**，否则每次增量都在浪费额度。

## 4. 目录与元数据

```
README.md  sources/  raw/  content/  assets/  data/  index/  scripts/  reports/  state/
```
- `raw/` 存原始响应（不可再生、最珍贵）；`content/` 存 Markdown；`data/` 存 jsonl；`index/` 存 SQLite。
- 每页的元数据：标题、pageid、来源 URL、修订号与修订时间、抓取时间、主题、分类、别名、内容来源（wikitext/html/image_ocr）、页面状态标记（过期、待审核、疑似测试页、短页）、作者（SMW `#set`）、许可。
- **有冲突的说法分开保留，不编造数值**：社区评价类字段加「（社区编辑评价，非官方数据）」标注。

## 5. 转换与切块的坑

- **wikitext → Markdown**（mwparserfromhell）：模板写成「**模板名** + `- 键: 值`」列表；嵌套模板用 `〔名：参数1，参数2〕`；`<br>` 要在 `strip_code` **之前**替换，否则换行会丢。
- **伪表格**（用模板拼出的表）会生成一个 16.8 万字的块 → 回退成逐行输出，再加 `hard_split` 兜底。
- HTML 里 `<dl>` 嵌套会触发 RecursionError；`colspan` 只写一次；`{{{参数}}}` 残留要剥掉；面包屑只在含「>」时才算。
- 切块：按标题切，目标 1,200 字、上限 2,400；表格按行切并重复表头；超长信息框按行切并标「（续）」。每块文本前加「《标题》> 章节路径」作为上下文。

## 6. 检索与问答链

- **中文全文检索**：SQLite FTS5 + 自建单字和双字列（`unicode61` 不会切中文）。BM25 权重：标题 10、章节标题 3、正文 1。代价是索引比原文大好几倍（约 3,650 万字的分块文本 → 308 MB 索引），可以接受。
- **实体库**（`entities.sqlite`）：实体表、字段表（EAV，存模板参数原文）、宽表（例如 `ships`）、别名表。日期只做格式标准化，原文保留在 `*_raw` 列，占位符不做推测。
- **别名来源**：重定向、模板里的别名字段、站内「昵称术语查询」页（只保留能对上现有标题的）。
- **问答入口 `ask.py`**：解析问题（类型、阵营、稀有度、年份、实体名或昵称、意图）→ 路由到 list / entity / fulltext → 输出带来源的证据包。列举类的名单必须来自结构化表（完整名单），不能拿全文检索的前几条充当。
  - 坑：整句问题直接丢进全文检索，命中会很差 → 先抽关键词，再匹配标题。
  - 坑：在榜单页里按名字搜，会把 A 条目里**顺带提到**的 B 算成 B 的排名 → 每条提及标成「针对该实体」或「顺带提及」。
  - 每个答案都附数据边界说明（未实装数量、未填日期、社区观点、图片识读可能有误）。
- 项目里写一份 `CLAUDE.md`，规定 AI 作答必须先走检索链、给出处、不凭记忆作答。
- **评测**：至少 10 个真实问题，自动核对路由和关键事实（`eval_search.py`、`eval_ask.py`），每次重建后都跑。

## 7. 图片：按价值分级，信息只在图里的要识读

- 全站图片约 20 万张，绝大多数是头像和图标 → 只解析地址并下载**攻略类主题的图**（单页上限 30 张）和**全部榜单大图**（不受单页上限）。
- 筛选榜单图：页面标题含「榜」，或文件名含 `榜|推荐|强度|排行|梯队|一图|天梯`；**排除装备「T0」图标**（`T\d\.(png|jpg)$`），否则会混进几十张小图。
- 图片记录写进 `data/assets.jsonl`（页面、文件、原图地址、本地路径、kind）；筛选规则写进下载脚本本身，保证重跑时不被冲掉。
- **大图识读流程**（适用于强度榜、一图流、表格截图）：
  1. 原图切成 1400 px 块、相邻重叠 120 px，另出一张整图缩略图（`_overview.jpg`）用来看版式；
  2. 写一份公共任务说明（输出的 JSON 结构、只写图上读得到的内容、看不清就标 `uncertain`、只有立绘没有名字的不认人）；
  3. 子 Agent 每批处理约 45 块，**每读完一行块就存盘**（第一批因为上下文压缩丢过细节）；
  4. 名称核对：给子 Agent 一份名称表，并开放实体库别名表只读查询；`name` 保留图上写法，`canonical` 只填能唯一确认的正式名；
  5. 识读结果单独成页（明确标注「AI 图片识读，以原图为准」），进入全文索引，同时建 `rank_entries` 表，经别名解析到实体。
- **实体解析的坑**：别名同时指向两个实体时**标题优先**（「海伦娜·META」）；**按条目类型约束**，舰船只匹配舰船、装备只匹配装备（同名的「彗星」）；**单字简称不自动对应**（「若」）；「X改」剥掉后对应本名，但 **META 不剥**（META 是独立实体）。
- 打捞表、兑换表不是强度排名：问答时排在强度/推荐榜后面，列表概览里不显示。
- 子 Agent 的默认模型配置有误时会报 `model_not_found` → 显式指定 `model`。并发数遵守用户的子 Agent 上限设置。

## 8. 交付与分发

- 覆盖率报告：已发现 / 已构建 / 已排除 / 失败 / 不在清单里的失败；另附失败清单、质量抽样、检索评测、问答评测报告。
- **Git 只存不可再生的部分**（`raw/`、`sources/`、识读 JSON、`file_urls.json`、`assets.jsonl`、游标和限速状态、脚本、文档）；可在几分钟内重建的 `content/`、`index/`、`data` 构建产物写进 `.gitignore`（顺带避开 GitHub 100 MB 的单文件上限）。
- **原图放 GitHub Release**：按用途分包，用 `ZIP_STORED`（不压缩，字节原样保留）；清单（路径、大小、sha256、源站地址）进 Git；恢复脚本先从 Release 下载，缺图时回源站补，下载后逐张校验 sha256。**私有仓库**：社区和游戏素材不公开转载。
- `.gitattributes` 统一 LF，避免 `.sh` 在 Windows 上被改成 CRLF。
- 交付前做一次**全新 clone 验证**：重建、恢复图片、跑评测，结果要与本地一致。

## 9. Agent 自身的坑

- 用 heredoc 往 Python 源码里写 `\n`、`\\|`、行尾的 `\` 时，转义很容易出错（这次就有字面 `\n` 写进代码、续行被吃掉、`sed` 把一行改坏）→ 多行代码用 Edit/Write 或原始字符串，改完用 `ast.parse` 检查语法。
- 后台任务结束前不要预测结果，等通知；读子 Agent 的转录文件会撑爆上下文。
- 汇报时说清：做完了什么、哪些按默认处理、哪些需要用户决定；没验证的就写没验证。

## Scrapling 在这类项目里的定位

- **适合用的地方**：没有 API 的纯 HTML 站点（`Fetcher` 会话 + CSS 选择器 + `Response.markdown()`），`SitemapSpider` / `CrawlSpider` 做整站遍历，`crawldir` 断点续抓，`autothrottle_enabled` 加 `robots_txt_obey`。
- **不该用的地方**：站点有 MediaWiki 一类结构化 API 时，直接走 API；用 stealth、代理轮换、Cloudflare 求解去换额度属于规避限制。WAF 按次数计数，并发只会更快触发封禁。
